# 家味 · 改进建议清单

> 清点时间：2026-10-21 · 依据：全量代码走查（backend/src 12 个 Rust 文件、frontend/src 48 个文件、database 全套脚本），对照《功能点清单.md》。
> 排序原则：**先保命，再好用，最后才是花活**。

---

## P0 · 保命级：数据可能丢 / 项目可能没

这一层的问题有一个共同点——**平时感觉不到，出事那天想撞墙**。

### 1. 整个项目没有版本控制 ⚠️ 最紧急

项目根目录不存在 `.git`。7115 行 Vue + 约 4500 行 Rust + 8 个数据库脚本，目前只存在于这一块硬盘上。误删、误改、硬盘阵亡，任意一个发生就是从头再来。

**建议**（10 分钟）：
```bash
git init
# .gitignore: backend/target/ frontend/node_modules/ frontend/dist/ backend/uploads/ .env *.log
```
推一个私有远端（Gitee / GitHub private）。数据库备份工具做得那么认真（dump → verify-dump 回环验证），代码本身反而裸奔，说不过去。

### 2. 上传的封面图不在任何备份里

`database/tools/` 的备份体系非常完善（mysqldump 格式 + 校验和比对），但封面图落在 `backend/uploads/` 目录，**备份脚本完全不碰它**。库恢复之日，就是历史订单封面集体 404 之时（好在 `DishCover` 有 emoji 回退，不会白屏，但照片全丢）。

**建议**：`dump-database.mjs` 跑完后把 `uploads/` 一并打包（`uploads_<时间戳>.tar.gz`），README「运维」一节补一句「备份 = SQL + uploads 两部分」。

### 3. 账本 / 经期 / 快递三个模块没有导出，纯 localStorage

只有**学习**模块做了 JSON 导入导出（`StudyView.vue` + `docs/study-json-format.md`）。账本、经期提醒、快递取件码三个 store（`ledger.js` / `health.js` / `parcel.js`）纯内存宫殿——清浏览器数据、换手机、换浏览器，三个月账本直接清零，且没有任何找回手段。

**建议**：三个 store 各加「导出 JSON / 导入 JSON」。学习模块的实现可以直接抄（都是 Pinia store，导出 state 即可）。成本半天，收益救命。

### 4. 默认连接串 `root:root@169.254.104.35`

两个问题：
- `169.254.x.x` 是**链路本地地址**（APIPA，通常是 DHCP 失败时的自配地址）。电脑网络环境一变（换路由器、换 WiFi、IP 重分配），后端就连不上库，而失败表现是「自动进离线演示模式」——用户以为系统正常，其实在跟内存数据玩。
- MySQL `root` 账号联网直连，权限过大。

**建议**：`.env` 改为首次启动时交互式生成（或至少提供 `.env.example`）；数据库建专用最小权限账号（如 `family_dining_app`，仅对 `family_dining` 库 CRUD）；README 的「当前部署状态」把地址来源写清楚。

## P1 · 好用级：日常体验提升最大

### 5. 采购清单不能手动加东西

清单完全由订单明细计算（视图 `v_order_shopping_preview` + `mock.computeShoppingList` 同逻辑）。「顺便买瓶酱油」「带包纸巾」「买猫粮」这种需求**加不进去**，只能靠自己脑子记——一个采购清单居然记不住采购时要顺手买的东西，存在感直接减半。

**建议**：`shopping_item` 支持手动项（加 `is_manual` 标记 + 名称/数量/单位/分类字段），或前端加「临时添加」输入框，归到「其他」分组。UI 上一个小输入框的事，数据库侧加几个字段的事。

### 6. 不是真 PWA（名不副实的那条）

README 写着「支持添加到主屏幕当 App 用」，但全库 grep 不到 `manifest` 和 `serviceWorker`——没有 manifest、没有 Service Worker。实际效果：加到桌面后**没有独立图标、没有全屏、没有离线缓存**，断网时连页面都加载不出来（离线演示模式也得先把页面下载下来才能演）。

整个前端是 mobile-first 设计，这是所有建议里**性价比最高**的一项：
- `public/manifest.webmanifest`：名称、图标（用 DishCover 的 emoji 渲几张 PNG）、`display: standalone`、主题色；
- 一个缓存静态资源的 SW（Vite 产物 hash 稳定，cache-first 即可）；
- iOS 补 `apple-touch-icon` 和 `apple-mobile-web-app-capable`。

### 7. 四大本地工具的数据不互通——家庭场景的核心裂缝

「家庭」系统的卖点是共享，但账本 / 经期 / 快递 / 学习四个模块的数据各锁在各自设备的 localStorage 里：妈妈记的账爸爸看不到，老人那边的取件码没人知道到期。而 MySQL 库、API 框架、Pinia store 全是现成的。

**建议分两步走**：
- **短期**（不做后端）：导出 JSON → 微信发家人 → 对方导入。学习模块已有雏形，把姿势复制到另外三个模块；
- **中期**：四个模块服务端化。表结构不复杂（`ledger_entry` / `parcel` / `member_cycle` / `study_*` 各一两张表），路由模式照 `basics.rs` 抄即可。做完这个项目才真正配得上「家庭」两个字。

### 8. README 落后代码一个版本

README 还停在初版：图片上传、常用功能四大工具、18 个路由、多月历统计……全没提（《功能点清单.md》第六节已列出差异表）。新用户照 README 会严重低估这个项目的完成度。

**建议**：把《功能点清单.md》的精简版合并进 README 功能一览表，或在显著位置链接过去。

### 9. 一键启动只有 Windows

`start.bat` 是好文明（自动装依赖 → build → 生成 .env → cargo run），但家里万一有台 Mac / Linux 机器想当服务器，只能手动抄四步。

**建议**：补一个等价 `start.sh`（同样逻辑，20 行），README 快速开始补一行。

## P2 · 进阶：长期健康与差异化

### 10. 后端零测试

全库没有一个 `#[test]`。偏偏最容易出 bug 的逻辑都在后端：订单状态机流转、顺手建档事务、`refresh_recipe_stats` 全量重算、份数换算。数据库侧已有 `e2e-write-test.mjs` 写链路回归，后端反而是裸的。

**建议**：优先给 `orders.rs` 的状态流转和统计重算加单测；CI 暂时不用，本地 `cargo test` 能跑起来就是巨大进步。

### 11. 页面与组件开始膨胀

`HomeView.vue` 705 行、`StudyQuizView.vue` 614 行、`study.js` store 859 行。还没到不可维护，但趋势明显。

**建议**：趁现在拆——首页轮播卡抽成 `<HomeCarouselCard>`，`study.js` 按 quiz / word / note 拆三个 store 文件。

### 12. 提醒只在打开 App 之后存在

经期提醒、快递待取全靠在首页轮播卡露脸（`HomeView`），不打开 App 就什么都不知道。接上第 6 条的 Service Worker 后，可以加 Notification API：定时（或后端轮询 `/api/reminders`）推送「明天经期预计来潮」「有 2 个快递待取」。

### 13. 菜单模板 / 一键复用

「周末聚餐」「生日宴」「火锅局」这种固定组合，现在每次从菜谱库重新点一遍。

**建议**：加 `menu_template` 表（名称 + 菜品 + 份数），点餐页一键「按模板下单」。数据模型简单，复用现有下单接口即可。

### 14. 快递100 是死配置

`config.rs` 和 `start.bat` 都预留了 `KUAIDI100_KEY / KUAIDI100_CUSTOMER`，但**没有任何调用方**。取件码页面已经存了运单号和 `com` 公司编码，数据模型都 ready 了。

**建议**：要么实现物流轨迹查询（取件码卡片显示「已到驿站 / 运输中」），要么删掉配置项——留着一个永不生效的开关，只会误导后来人。

### 15. 推荐算法可以再进一步

现在是「避开最近 7 天 + 荤素汤搭配」（`stats.rs` 的 suggestion）。两个低成本的增强：
- **忌口过滤**：`member` 表加 `dislikes` 字段，推荐时排除含忌口食材的菜；
- 极简「冰箱库存」：标记家里现有的食材，推荐优先消耗快过期的。

## 附：不建议做的（防止用力过猛）

- **不做重权限体系**。免密码切头像的特性不是缺陷，是精心设计的家庭场景解法。真要安全，上「家庭 PIN 码」这种轻量方案就够了。
- **不引 UI 框架**。手写 CSS 的轻量感（首屏几十 KB）是优点，Vuetify / Element Plus 会让体积和心智负担一起翻倍。
- **不微服务化、不拆库**。单库、单端口、一条 `start.bat` 是家庭项目的最大美德。
