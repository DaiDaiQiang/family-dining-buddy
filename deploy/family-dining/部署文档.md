# 家庭点餐系统 · 正式环境部署文档（Windows 服务器）

> 目标：把打包产物部署到一台 Windows 服务器，单端口 8080 提供服务。
> 前后端**不分离**：一个 `family-dining-api.exe` 进程同时提供 API 与前端页面，双击即跑。

---

## 一、部署包结构

打包产物目录 `family-dining/` 结构如下：

```
family-dining/
├─ bin/
│  └─ family-dining-api.exe       # 后端可执行文件（同时托管 API + 前端静态页）
├─ dist/                          # 前端 Vue 构建产物（后端静态托管，无需单独服务器）
├─ uploads/                       # 已上传的头像图片（历史数据，勿删）
├─ database/
│  ├─ 01_schema.sql               # 建表脚本
│  ├─ 02_seed_data.sql            # 示例数据
│  ├─ 03_phase1_family_hub.sql    # 阶段 1 迁移
│  ├─ 04_phase2_profile_reminder.sql  # 阶段 2 迁移
│  ├─ 05_member_avatar_url.sql    # 阶段 5 迁移
│  ├─ 06_system_version.sql       # 系统版本记录迁移
│  ├─ 07_consumable.sql           # 阶段 3 · 耗材维护与消耗统计
│  └─ tools/                      # 数据库运维工具（含 mysql2 依赖）
├─ .env.production.example        # 正式环境配置模板
├─ start-prod.bat                 # 正式环境启动脚本（一键启动）
└─ 部署文档.md                     # 本文档
```

> **为什么前后端不分离？** 前端 `npm run build` 编译成纯静态文件放进 `dist/`，
> 后端启动时把 `dist/` 当静态资源托管出去，`/api/*` 走同源接口。
> 浏览器只访问 `http://服务器:8080` 一个地址，页面和接口都从这个进程出来，
> 不需要 Nginx、不需要单独起前端服务。

## 二、前置条件

| 依赖 | 版本 | 说明 |
|------|------|------|
| Windows Server | 任意 | 建议 Win Server 2016+ 或 Win10/11 |
| MySQL | 8.0.16+ | 必须（用到 CHECK 约束、生成列、窗口函数） |
| Node.js | 18+ | 仅用于跑数据库运维脚本（建库/迁移），服务运行时不依赖 |
| 后端 exe | 已打包 | 无需再装 Rust 工具链 |

## 三、部署步骤

### 第 1 步：放置部署包

把 `family-dining/` 整个目录拷到服务器，例如：

```
D:\family-dining\
```

### 第 2 步：配置环境变量

1. 复制模板：
   ```bat
   copy .env.production.example .env
   ```
2. 编辑 `.env`，至少改以下三项（**其余见模板内注释**）：
   - `DATABASE_URL` —— 改成正式库的账号密码与地址
   - `AUTH_SECRET` —— 改成一段随机长字符串（务必改！默认值可被伪造令牌）
   - `STATIC_DIR` / `UPLOAD_DIR` —— 改成服务器上的**绝对路径**（默认模板已按 `D:\family-dining\` 写好）

   > 生成随机密钥：`openssl rand -hex 32`（或用任意 32 位以上随机串）

### 第 3 步：初始化数据库

在服务器上，`cd` 到 `database\tools` 目录，配置连接信息后执行：

```bat
cd D:\family-dining\database\tools

REM 用环境变量覆盖连接信息（不设则用脚本内置默认值）
set DB_HOST=127.0.0.1
set DB_PORT=3306
set DB_USER=你的数据库管理员账号
set DB_PASSWORD=你的密码
set DB_NAME=family_dining

REM 3.1 建库建表 + 导入示例数据（跑 01/02/03）
npm run apply

REM 3.2 补齐全部阶段迁移（跑 03/04/05/06/07，幂等，可重复执行）
npm run migrate
```

> `apply` 执行 `01_schema.sql`（建库建表）、`02_seed_data.sql`（示例数据）、
> `03_phase1_family_hub.sql`（阶段 1）。
> `migrate` 补齐 03/04/05/06/07（含系统版本记录表 + 耗材模块）。两者都幂等，重复执行不破坏数据。

**验证**：`npm run apply` 末尾应输出 `✓ 数据库初始化完成`，且 `表：17`、`视图：5`、`存储过程：2`。

### 第 4 步：防火墙放行 8080

- 入站规则放行 TCP 8080（仅限内网的话，可只对内网网段放行）。

### 第 5 步：启动服务

双击 `start-prod.bat`，或在命令行：

```bat
cd D:\family-dining
start-prod.bat
```

启动成功后浏览器访问：

```
http://服务器IP:8080
```

看到首页即部署成功。手机/平板同一内网下也能访问，**无需任何前端单独配置**。

## 五、常见问题

**Q1：启动后访问首页是空白 / 404？**
确认 `dist/index.html` 存在，且 `.env` 里 `STATIC_DIR` 指向了正确的绝对路径。

**Q2：接口报「数据库未就绪」？**
检查 MySQL 服务是否运行、`.env` 的 `DATABASE_URL` 是否正确、是否已执行建库迁移。

**Q3：登录后马上被踢回登录页？**
`AUTH_SECRET` 与之前不一致（换机器/改配置），令牌失效属正常，重新登录即可。正式环境部署后应保持密钥不变。

**Q4：头像不显示？**
`UPLOAD_DIR` 指向错误，或 `uploads/` 目录未随包拷到服务器。历史头像已包含在部署包里。

**Q5：耗材页（工具 → 耗材）报错或找不到？**
确认已执行 `npm run migrate`（07 迁移建 `consumable` / `consumable_log` 表），且后端 exe 为本次打包的最新版。

**Q6：菜谱导入（下厨房链接）导入失败？**
本功能依赖后端主动抓取下厨房网页。**下厨房对服务器出口 IP 普遍做 302 人机验证（captcha）**，
在云服务器/机房环境大概率不可用，家庭宽带 IP 可能可用。导入失败时系统会给出友好提示，
不影响其它功能。若服务器环境确实不可用，请改用手动录入菜谱。

**Q7：想让服务开机自启、后台常驻？**
当前 `start-prod.bat` 是前台运行（关窗口即停）。正式环境建议用 NSSM 或 Windows 服务注册为系统服务。需要的话可进一步配置。

**Q8：前端更新后怎么生效？**
把新的 `dist/` 覆盖到服务器对应目录，重启 exe 即可，无需重编后端。
