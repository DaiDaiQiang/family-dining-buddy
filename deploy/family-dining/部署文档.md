# 家庭点餐系统 · 正式环境部署文档（升级已有环境）

> 本包用于**升级一台已部署过本系统的 Windows 服务器**。
> 前后端不分离：一个 `family-dining-api.exe` 同时提供 API 与前端页面。
> 数据库侧**只包含增量迁移脚本**（新增/修改的表结构），不重建全库、不清数据。

---

## 一、部署包结构

```
family-dining/
├─ bin/
│  └─ family-dining-api.exe       # 后端（同时托管 API + 前端静态页）
├─ dist/                          # 前端构建产物（后端静态托管）
├─ uploads/                       # 已上传的头像/图片（历史数据，勿删）
├─ database/
│  ├─ 03_phase1_family_hub.sql    # 阶段 1 迁移
│  ├─ 04_phase2_profile_reminder.sql  # 阶段 2 迁移
│  ├─ 05_member_avatar_url.sql    # 阶段 5 迁移
│  ├─ 06_system_version.sql       # 系统版本记录
│  ├─ 07_consumable.sql           # 阶段 3 · 耗材维护与消耗统计
│  ├─ 08_shared_data.sql          # 学习模块 · 家庭共享数据（公有题库）
│  └─ tools/                      # 迁移工具（仅 migrate.mjs + sql-runner.mjs + mysql2）
├─ .env.production.example        # 配置模板
├─ start-prod.bat                 # 启动脚本
└─ 部署文档.md                     # 本文档
```

> **注意**：本包**不含** `01_schema.sql`（建库）和 `02_seed_data.sql`（示例数据）。
> 这些只在首次全新部署时用，升级环境**不要**执行它们。

## 二、升级步骤（已有环境）

### 第 1 步：备份（务必）

升级前先备份数据库和当前部署目录，以防万一：

```bat
REM 备份数据库（在服务器上执行，用 mysqldump）
mysqldump -u root -p family_dining > backup_升级前_%date:~0,10%.sql

REM 备份部署目录
xcopy D:\family-dining D:\family-dining_backup_升级前 /E /I /Y
```

### 第 2 步：停止旧服务

关闭正在运行的 `start-prod.bat` 窗口（或停止服务）。

### 第 3 步：更新文件

用本包覆盖服务器上 `D:\family-dining\` 下的对应内容：

- `bin\family-dining-api.exe` → 覆盖旧 exe
- `dist\` → 覆盖旧 dist（**先清空再拷入**，避免残留旧版 js）
- `database\` → 覆盖迁移脚本与 tools
- `uploads\` → 合并（不要删服务器上已有的头像）

> `.env` 若已存在，**保留旧的不要覆盖**（里面是你配好的连接串和密钥）。
> 首次部署才需要 `copy .env.production.example .env`。

### 第 4 步：数据库增量迁移

```bat
cd D:\family-dining\database\tools

REM 用环境变量指定连接（不设则用内置默认值）
set DB_HOST=127.0.0.1
set DB_PORT=3306
set DB_USER=你的数据库账号
set DB_PASSWORD=你的密码
set DB_NAME=family_dining

npm run migrate
```

> `migrate` 按序执行 03~08，**全部幂等**（已存在的表/列自动跳过），
> 不会清空或覆盖已有业务数据。输出末尾应看到 `✓ 迁移完成`，
> 且 `shared_data`、`consumable` 等表标记为「✓ 已就绪」。

### 第 5 步：启动服务

双击 `start-prod.bat`，浏览器访问 `http://服务器IP:8080` 验证。

## 四、常见问题

**Q1：`npm run migrate` 报「找不到 03_xxx.sql」？**
确认 `database/` 目录下 03~08 六个 .sql 文件齐全，且 tools 里 `migrate.mjs`、`sql-runner.mjs` 都在。

**Q2：迁移后登录被踢出？**
若 `.env` 的 `AUTH_SECRET` 被意外改动，旧令牌会失效，重新登录即可。正常升级应保留原 `.env` 不变。

**Q3：前端页面出现旧功能/空白？**
`dist` 没清空导致新旧 js 混在一起。清空 `dist/` 后重新解包覆盖，重启 exe。

**Q4：菜谱导入（下厨房链接）失败？**
该功能依赖后端抓取下厨房网页，服务器出口 IP 常被 302 人机验证拦截，属已知限制，不影响其它功能。

**Q5：想让服务开机自启？**
当前是前台运行。可用 NSSM 或注册 Windows 服务实现常驻，需要可进一步配置。
